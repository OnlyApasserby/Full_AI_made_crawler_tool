# 阶段 02：静态抓取与页面解析

## 阶段目标

- 熟练使用 `requests.Session`，理解连接池、线程局部 Session、流式读取；
- 掌握页面解析的两种路线：内置正则解析与 bs4+lxml 选择器，以及项目的降级策略；
- 理解 robots.txt 的语义，能判断"某 UA 能否抓某路径"。

## 2.1 requests 核心

### 2.1.1 Session 与连接池

`requests.get()` 每次都会新建连接；`requests.Session()` 在多次请求间**复用 TCP 连接（keep-alive）**，并自动管理 Cookie。爬虫抓取量大，必须用 Session。

### 2.1.2 线程局部 Session（项目关键技巧）

多线程爬虫里，一个 Session 被多个线程共享会踩坑（Cookie 串味、连接池竞争）。项目的做法是**每个线程一份 Session**：

- `core/fetcher/requests_fetcher.py`：`threading.local()` 持有 Session，线程第一次用时才创建，随线程消亡而释放；
- 抓取时流式读取（`stream=True`）+ 大小上限，防止把一个巨大文件读进内存；
- 媒体直链不做二次回读（拿到 URL 就够，体积交给下载器的 `Range: bytes=0-0` 探测）。

### 2.1.3 编码推断

响应编码猜错 = 满屏乱码。顺序：响应头 `Content-Type` 的 charset → meta 标签 → `apparent_encoding`（chardet/charset_normalizer 统计推断）。项目实现在 `core/fetcher/base.py`。

### 2.1.4 抓取契约：`BaseFetcher`

`core/fetcher/base.py` 定义统一契约（`BaseFetcher.fetch()` / `FetchContext` / `NetworkEvent`）：静态 fetcher 与动态 fetcher 对上暴露同一接口，上层（提取/下载流水线）不关心背后是 requests 还是浏览器。**面向接口编程**的活教材，阶段 07 的登录态句柄也遵循同一契约。

## 2.2 页面解析

### 2.2.1 内置正则解析 `core/parser.py`

零依赖，覆盖爬虫 80% 的日常需求：

| 函数 | 作用 | 学习点 |
|---|---|---|
| `extract_links` | 提取 `<a href>` 链接 | `urljoin` 相对转绝对；去 `script/style` |
| `extract_media_links` | 提取图片/视频/音频直链 | 覆盖懒加载属性（`data-src` 等）、`srcset` 多候选、`poster`、`og:video`、JS 内嵌直链 |
| `extract_text` | 提取正文文字 | 去标签、HTML 实体还原 |

**为什么值得学**：正则解析快、无依赖、行为可预测；缺点是脆。项目对"缺依赖"和"简单站点"两条退路都保留了它（见下）。

### 2.2.2 bs4 + lxml 选择器

`beautifulsoup4 + lxml` 提供完整 CSS 选择器/XPath 能力。项目在两处使用，且都带**降级**：

- `core/extractor/rule_extractor.py`：站点规则用 CSS 选择器；缺失时退回 `parser.py` 的简化选择器；
- `core/ebook_fetcher.py`：电子书正文抓取，多级选择器（正文容器 / 噪声节点 / 下一页链接），bs4 缺失时退正则。

**工程启示**：可选依赖不应是"装了才能用"，而要"缺了就降级，并在日志里说清楚"——这是项目一贯的风格，写自己的爬虫时也建议照做。

### 2.2.3 robots.txt：`core/robots.py`

robots.txt 是站点对爬虫的**声明**（不是技术强制，但是行业规范与法律 Risk 的分界线）。项目实现要点：

- 按 User-Agent 分组匹配，**最长匹配优先**；
- 同一组内 **Allow 优先于 Disallow**；
- `RobotsCheckThread` 后台线程在线抓取 robots.txt，供界面预览与抓取前校验。

```python
from core.robots import RobotsParser
# 伪代码示意：parser.allowed(path, user_agent) -> bool
```

**红线**：robots.txt 是本项目唯一的硬性闸门，任何功能（包括合规筛查自身）都遵守它。

## 2.3 源码精读清单

| 文件 | 重点看什么 |
|---|---|
| `core/fetcher/base.py` | `BaseFetcher`/`FetchContext`/`NetworkEvent` 契约；编码推断；可中断睡眠 |
| `core/fetcher/requests_fetcher.py` | 线程局部 Session、流式+上限、`fetch_prefix` 头部探测、Cookie jar 注入 |
| `core/parser.py` | 三个 extract 函数的属性覆盖清单；实体还原表 |
| `core/robots.py` | UA 分组、最长匹配、Allow 优先的实现 |
| `core/ebook_fetcher.py` | 选择器优先/正则降级的双轨写法；`visited` 防死循环；`max_pages` 终止；指数退避 |

## 2.4 动手练习

1. **用项目的 fetcher 抓一页**：`from core.fetcher import RequestsFetcher`（以实际导出为准），抓 `https://example.com`，打印 `ctx.text` 前 300 字符与最终编码；
2. **解析对比**：分别用 `core.parser.extract_links` 和一段你自己写的 bs4 代码提取同一页面的全部链接，比较结果差异（提示：懒加载站点差异最大）；
3. **robots 判定**：给 `https://www.baidu.com`（或任一站点）写脚本：抓 robots.txt → 用 `RobotsParser` 判断 `/robots.txt` 自身与一个深层路径在 UA=`*` 下是否允许，并解释"Allow 优先"在哪一行生效；
4. **降级体验**：临时 `pip uninstall beautifulsoup4 lxml`（在虚拟环境里操作），跑一次站点规则提取或 ebook 抓取，观察日志中的降级提示，然后装回；
5. **编码实验**：找一个 GBK 编码的页面，先按错误编码解码看乱码，再用项目的编码推断顺序拿到正确文本。
