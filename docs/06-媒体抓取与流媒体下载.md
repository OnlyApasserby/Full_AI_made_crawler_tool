# 阶段 06：媒体抓取与流媒体下载

> 本阶段是全项目技术密度最高的部分，建议分配 1~2 周。媒体链路：
> **fetcher → extractor → paginator → pipeline → downloader**，流媒体另有 `core/media/` 专攻。

## 阶段目标

- 能画出媒体抓取全链路并说清每个环节的职责边界；
- 掌握提取器插件体系的设计（契约 + 注册表 + 优先级）；
- 掌握分层质量过滤与多层去重；
- 掌握 Range 断点续传下载；
- 能手动解析 m3u8/mpd 并完成 HLS/DASH 的下载合并（含 AES-128）。

## 6.1 链路全景

```
起始URL ─▶ fetcher ──▶ extractor ──▶ paginator ──▶ pipeline ──▶ downloader
           抓页面      提取媒体URL    翻页找更多    去重/质量过滤   下载/续传/校验
                        │                      │
                        └─ 站点规则命中优先 ────┘
```

编排者在 `core/media_crawler.py`（`MediaCrawlThread`）：串联各环节、静态不足自动升级渲染、`BoundedSemaphore` 限流、翻页与详情页两级跟随。

## 6.2 提取器插件体系：`core/extractor/`

这是本项目**最值得学的设计模式**：

| 组件 | 职责 |
|---|---|
| `base.py` | 契约：`can_handle(html/url)` 返回置信度 + `extract()` 返回媒体项；带优先级 |
| `registry.py` | 插件发现 / 按优先级调度 / `extract_all` 合并结果；`sites/` 目录即插即用 |
| `generic_html.py` | 通用 HTML 提取：每个标签取最高质量地址、`srcset` 最大候选、CSS 背景图、`og:` 标签、缩略图猜原图 |
| `generic_json.py` | 接口 JSON 提取：键名足够具体才采纳（防误报） |
| `network.py` | XHR 监听落地：转发请求头过防盗链、过滤埋点/广告域名 |
| `rule_extractor.py` | **站点规则 JSON 热加载**：不改代码适配新站；bs4 缺失退简化选择器 |

**站点规则**（`resources/rules/*.json`，模板 `_template.json`）：用选择器/正则描述目标站结构，界面里可"抓取并测试"验证命中数，"保存并重载"立即生效。学习时重点体会：**把"适配新站点"从改代码变成改配置**，是爬虫工具可维护性的分水岭。

## 6.3 翻页策略：`core/paginator.py`

三种策略（`PageRule` 描述）：

1. **next_link**：跟随"下一页"链接，`rel=next` 优先，辅以文本特征；
2. **page_param**：接口模板翻页（`?page=N`）；
3. **api_offset**：偏移量翻页。

工程克制点：`auto` 模式只做**有信号推断**（`?page=N`、`/list_2.html` 路径末段数字），不瞎拼接 URL；`_pick_next` 取页内最小页码；同站判定剔除跨站链接与媒体直链。

## 6.4 质量过滤与去重：`core/pipeline.py`

`MediaPipeline` 的核心思想是**从便宜到昂贵分层过滤**，每一层挡掉一批，越贵的检查放到越后：

```
类型识别 → SVG/图标 → 屏蔽正则 → URL归一化去重 → 体积/尺寸 → 编号限流
```

配合 `core/downloader.py` 的**下载后落地校验**，形成"提前过滤 + 下载后闭环"：

- 类型唯一口径：`core/media/detector.py`（扩展名 / Content-Type 双通道，优先级表裁决）；
- 尺寸探测：`core/media/probe.py`（Pillow + 内置文件头解析，Pillow 缺失降级）；
- 精确去重：图片 MD5；近似去重：dhash 感知哈希；
- `FilterStats` 统计每层拦掉多少——**没有统计的过滤是不可调的过滤**。

## 6.5 下载器：`core/downloader.py`

- `PriorityQueue` + 线程池并发下载（`manager/thread_manager.py` 的 `spawn_workers` 提供工作线程）；
- **Range 断点续传**：1MB 分块；续传前校验 `Content-Range` 起点与本地字节数一致，不一致从头下；
- `Range: bytes=0-0` 轻量探测：只取 1 字节就拿到 `Content-Range` 里的总大小，不浪费流量；
- MD5 完整性校验（Digest / Content-MD5）；
- 下载完成后生成 `index.html` / `resources.txt` 清单。

## 6.6 流媒体：`core/media/`

### 6.6.1 HLS：`hls.py`

m3u8 是 HLS 的播放列表（文本格式，最适合教学）：

- 主播放列表（多码率）vs 媒体播放列表（分片）；
- `EXT-X-KEY` + `AES-128` 加密分片；
- `EXT-X-MAP` 初始化段、`EXT-X-BYTERANGE` 字节范围分片；
- 直播标记与多码率优选。

### 6.6.2 DASH：`dash.py`

MPD（XML）解析：`SegmentTemplate` / `SegmentTimeline` / `SegmentList` / `SegmentBase` 四种寻址方式、`BaseURL` 层级拼接、音视频分离轨道的处理。

### 6.6.3 合并：`merger.py`

- **边下边写**：分片按序写文件，不全下完再合并（省磁盘、可断点）；
- 并发下载 + 按序合并（乱序到达、顺序落盘）；
- AES-128 分片解密（`pycryptodome`，缺失时给出明确提示而非静默失败）；
- ffmpeg `-c copy` 转封装为 MP4（无 ffmpeg 时保留 `.ts`）；
- `fetch_bytes` 回调解耦网络层——**合并器不关心分片从哪来**，可单测。

## 6.8 动手练习

1. **链路示踪**：GUI 里发起一次媒体抓取，对照日志逐行指出"现在走到链路哪一环"；
2. **写一条站点规则**：照 `_template.json` 给一个小图站写规则 → 「抓取并测试」看命中数 → 保存重载 → 再抓一次验证生效；
3. **手动解 m3u8**：找一个公开 HLS 测试流（如 `https://test-streams.mux.dev/x36xhzz/x36xhzz.m3u8`），写脚本解析主列表→选码率→解析媒体列表→打印分片数；
4. **下载合并**：用项目的 merger（或你的脚本）下载练习 3 的全部分片并合并成 `.ts`，装 ffmpeg 后转 `.mp4` 用播放器验证；
5. **AES-128**：找一个加密测试流（如 Big Buck Bunny 的加密变体），验证解密合并后能播放；
6. **Range 续传**：下载一个大文件中途 kill，重启续传，对比日志中的 `Content-Range` 校验；
7. **去重效果**：对同一图集抓两次，统计 `FilterStats` 各层拦截数，解释每一层为什么拦。
