## 10.2 综合项目一：静态新闻聚合爬虫

**目标**：从多个新闻站点聚合文章标题、链接、时间，落 SQLite，支持重启续爬。

要求：

- BFS 深度 ≤ 2，同站限定（用 `URLFilter` 白名单）；
- URL 归一化去重 + `crawled_urls` 台账（参考 `manager/db_manager.py` 表设计）；
- 每站抓取前校验 robots.txt；
- 请求间隔抖动 + UA 池；
- 支持 Ctrl+C 优雅停止，重启后不重复抓；
- 输出 CSV 汇总。

验收：中断重启无重复；robots 拒了的路径一条都没抓；CSV 字段完整。

## 10.3 综合项目二：图站媒体爬虫

**目标**：抓取一个公开图站（或相册页）的全部原图，自动翻页 + 详情页两级跟随。

要求：

- 静态优先，产出不足自动升级 Playwright 渲染（仿 `_should_escalate`）；
- 跟随懒加载（自动滚动）；
- 提取用"每标签最高质量地址"策略（参考 `generic_html.py`）；
- 过 `MediaPipeline` 分层过滤：类型 → 屏蔽正则 → 归一化去重 → 尺寸/体积；
- 下载带 MD5 精确去重 + dhash 近似去重；
- 生成 `index.html` 清单。

验收：重复图被 MD5/dhash 拦下且统计可见；缩略图不当作原图（或能解释取舍）；断网重跑不重复下载。

## 10.4 综合项目三：流媒体下载器

**目标**：输入一个 m3u8/mpd 地址，下载合并为可播放文件。

要求：

- 解析主/媒体播放列表，多码率优选；
- 支持 `EXT-X-KEY` AES-128 解密（无密钥库时给明确提示）；
- 支持 `EXT-X-MAP` 与 `EXT-X-BYTERANGE`；
- 分片并发下载、按序合并、边下边写；
- 装 ffmpeg 后转封装 MP4；未装保留 `.ts`；
- 中断后续传（分片级断点）。

验收：三个不同测试流全部合并成功且可播放；加密流解密后播放正常；中途 kill 后续传不重下已完成分片。

## 10.5 综合项目四：带登录态的采集器

**目标**：采集一个需要登录的页面（用**你自己的账号**，仅练习用途）。

要求：

- 用 `core/browser_session` 复用本人登录态（先完全退出浏览器）；
- `check_login()` 三通道理解并选用合适规则（元素级选择器优先）；
- 登录态失效时按 `relogin_hint()` 人工重登后重新导出；
- 同一登录态同时喂 requests 与浏览器，对比结果；
- Cookie 加密导出，`resources/sessions/` 不入库；
- 全程遵守 robots.txt 与该站条款。

验收：能稳定复现"带登录态抓取"；说得清每一步的合规边界；Cookie 文件加密且未提交 git。

## 10.7 继续进阶方向

- **规模化解**：单机 SQLite → Redis 分布式队列 + 去重；`scrapy` 框架对照本项目理解其组件（引擎/调度器/下载器/管道）；
- **渲染规模化**：浏览器集群与指纹管理（继续坚守"一致性 + 拟人化"边界）；
- **数据侧**：从"存下来"到"用起来"：清洗、结构化、增量更新；
- **合规深化**：把 `core/compliance/` 的思路用于任何采集项目的前置审查；
- **性能**：asyncio + aiohttp 与多线程的取舍；连接池/超时/重试参数调优。

> 最后提醒：技术能力越大，越要把"robots.txt 是硬闸门、登录态只用本人的、不绕过任何验证与限制"当作默认姿势。本方案教的所有对抗手段，目的都是**礼貌、稳定、可追溯地获取公开数据**。
