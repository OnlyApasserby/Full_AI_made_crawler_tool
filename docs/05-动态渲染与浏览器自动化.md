# 阶段 05：动态渲染与浏览器自动化

## 阶段目标

- 理解什么时候必须用浏览器：SPA、懒加载、XHR 数据接口、强反爬；
- 掌握 Playwright 的基本招式：持久化上下文、网络事件监听、自动滚动；
- 理解浏览器资源管理：线程局部复用、并发限流、stealth 注入；
- 理解"静态不足自动升级渲染"的策略设计。

## 5.1 为什么需要浏览器

裸 requests 只能拿到"服务器直出的 HTML"。以下场景必须真浏览器：

| 场景 | 现象 | 项目对策 |
|---|---|---|
| SPA / 前端渲染 | HTML 是空壳，数据由 JS 渲染 | `playwright_fetcher.py` 渲染后再取 |
| 懒加载 | 图片/视频在滚动到视口时才加载 | 自动滚动触发 |
| XHR/接口数据 | 内容走 JSON 接口，不在 HTML 里 | `page.on("request"/"response")` 网络监听 |
| 反爬指纹 | 裸请求头过于"干净" | 真实浏览器 + 一致 UA/Referer/Cookie |

代价：浏览器重（一个实例数百 MB 内存）、慢（渲染耗时）。所以项目的策略是**静态优先，不够再升级**。

## 5.2 Playwright 基础招式

- `launch_persistent_context(user_data_dir, ...)`：带用户数据目录启动——**登录态复用的基础**（阶段 07）；
- `page.on("request", handler)` / `page.on("response", handler)`：监听所有网络请求/响应，从中筛出媒体直链与数据接口（项目只采元数据，不落内容）；
- 自动滚动：逐步滚动页面触发懒加载，配合等待策略；
- 等待策略：`wait_for_selector` / 网络空闲，避免" DOM 还没渲染完就抓"。

## 5.3 项目的动态抓取层

### 5.3.1 `core/fetcher/playwright_fetcher.py`

Chromium 渲染 + 网络监听落地。与 `RequestsFetcher` 实现同一个 `BaseFetcher.fetch()` 契约，上层无感切换。

### 5.3.2 `core/fetcher/browser_pool.py`

浏览器不是每次抓取都启动（太贵），而是：

- `threading.local` 管理**线程内**浏览器实例的生命周期；
- `BoundedSemaphore` 跨任务限流：同时存在的浏览器实例有上限（浏览器是重资源，不限流会把机器拖垮）；
- stealth JS 注入：`navigator.webdriver` 等指纹补全（与阶段 07 `anti_detect` 同一思想）。

### 5.3.3 `core/fetcher/chrome_setup.py`

浏览器内核查找链（环境变量 `CRAWLER_CHROME_PATH` → `resources/browsers/` → 根目录已解压内核 → 系统 Chrome/Edge → PATH → 自动解压 `chrome-win64.zip`）。**离线优先**的设计让打包后的 exe 在没有网的机器上也能用。

### 5.3.4 自动升级策略

`core/media_crawler.py` 的 `_should_escalate()`：静态抓取产出的媒体不足、或页面带明显 JS 特征时，自动切到渲染模式重抓。这是"成本与覆盖率"的工程权衡：默认便宜，必要时才贵。

## 5.4 源码精读清单

| 文件 | 重点看什么 |

| `core/fetcher/base.py` | `BaseFetcher`/`FetchContext`/`NetworkEvent` 契约；可中断睡眠 |

## 5.5 动手练习

1. **渲染前后对比**：选一个 SPA 站点（或任一懒加载图站），分别用 `requests` 与 Playwright 抓同一页面，对比拿到的媒体链接数量；
2. **XHR 监听**：写 20 行 Playwright 脚本，`page.on("response")` 过滤出 `application/json` 响应，打印 URL 与数据片段——体会"页面数据其实在接口里"；
3. **懒加载触发**：对图站写自动滚动脚本，对比"不滚动"与"滚动到底"抓到的图片数；
4. **限流观察**：在 `browser_pool` 的限流上限内同时发起多个抓取任务，用任务管理器看浏览器进程数，验证不超过上限；
5. **内核查找**：`python -c "from core.fetcher import chrome_setup; print(chrome_setup.find_executable())"`，再设置 `CRAWLER_CHROME_PATH` 指向另一个内核，观察优先级变化。
