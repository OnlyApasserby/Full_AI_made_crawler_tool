# 阶段 01：爬虫基础与项目架构

## 阶段目标

- 能用一句话说清爬虫的工作闭环，并画出本项目的模块架构图；
- 补齐最小网络基础知识（URL、HTTP、状态码、常用请求头、编码）；
- 独立搭好项目环境，跑起 GUI、自检和单元测试；
- 理解项目"core → manager → ui"分层的原因。

## 1.1 爬虫是什么：一个闭环

```
        ┌──────────────────────────────────────────────┐
        │                                              │
        ▼                                              │
  ① 选一个 URL ──▶ ② 发 HTTP 请求 ──▶ ③ 拿到响应（HTML/JSON/二进制）
                                              │
                              ④ 解析：提取数据 + 发现新 URL
                                              │
                              ⑤ 存储：文件 / 数据库 / 去重登记
                                              │
                              ⑥ 新 URL 入队（控制深度、频率、范围）
```

爬虫的所有高级特性都是对这个闭环的增强：去重（⑥ 不重复入队）、限速（② 之间加延时）、断点续爬（⑤ 记住做到哪）、动态渲染（② 用真浏览器代替裸请求）、反爬对抗（② 伪装得更像人）。

## 1.2 最小网络知识集合

| 概念 | 要点 | 在项目的哪里用到 |
|---|---|---|
| URL 结构 | scheme://host:port/path?query#fragment；相对路径要 `urljoin` 转绝对 | `core/parser.py`、`core/media/models.py` 的 `normalize_url` |
| HTTP 方法 | GET 取数据、HEAD 探测（`Range: bytes=0-0` 轻量探体积） | `core/downloader.py` |
| 状态码 | 200 成功、301/302 重定向、403 拒绝、404 不存在、429 限流 | 全项目；`core/compliance/` 对 403/404 有专门处理 |
| 常用请求头 | `User-Agent`（身份）、`Referer`（防盗链）、`Cookie`（登录态）、`Content-Type`（类型） | `core/fetcher/requests_fetcher.py`、`core/extractor/network.py` |
| 字符编码 | charset 推断错误会乱码；`apparent_encoding` / meta charset | `core/fetcher/base.py` 的编码推断 |
| robots.txt | 站点对爬虫的声明，**硬闸门** | `core/robots.py`（阶段 02 细讲） |

## 1.5 项目架构导览

```
Full_AI_made_crawler_tool/
├── main.py          # 入口：QApplication + 主窗口 + Ctrl+C 安全退出
├── config.py        # 全部默认参数（COMPLIANCE_* / LLM_* / DEFAULT_SESSION_*）
├── models.py        # 数据模型（任务 / 配置 / 状态）
├── core/            # 爬虫核心：不依赖 UI，可独立单测
│   ├── fetcher/     #   统一抓取层：requests（静态）+ playwright（动态）
│   ├── extractor/   #   媒体提取器插件体系（规则/网络事件/HTML/JSON）
│   ├── media/       #   媒体领域层：类型识别/尺寸探测/流媒体(HLS·DASH)/合并
│   ├── browser_session/ # 登录态复用（可插拔模块）
│   ├── compliance/  #   合规辅助筛查
│   ├── crawler.py / downloader.py / media_crawler.py / paginator.py
│   ├── pipeline.py / parser.py / filter.py / robots.py / security.py
│   └── ebook_fetcher.py
├── manager/         # 任务调度：多任务队列、并发线程池、SQLite 管理
├── ui/              # PyQt6 界面（只做交互与信号连接，业务下沉 core/manager）
├── utils/           # UA 池 / URL 校验 / 格式化 / 日志
├── tests/           # 单元测试 + 集成测试
└── resources/       # 规则 JSON / 浏览器内核 / 会话配置 / 合规报告留档
```

**为什么这样分层**：`core/` 不 import 任何 Qt 组件，因此可以在无显示环境跑单元测试；`ui/` 只负责把用户操作翻译成对 core/manager 的调用、把 core 的信号翻译成界面刷新。这是"业务与界面分离"的经典工程实践，也是本方案反复强调的阅读顺序：**先 core，再 manager，最后 ui**。

**媒体抓取的数据流**（阶段 06 的主战场，先建立全景）：

```
起始 URL ─▶ fetcher(抓页面) ─▶ extractor(提取媒体URL)
   ─▶ paginator(翻页) ─▶ pipeline(去重/质量过滤) ─▶ downloader(下载/续传)
```

## 1.7 动手练习

1. **环境达标**：完成 §1.3，`python main.py --selftest` 无 FAIL；
2. **测试全绿**：`python -m pytest tests/ -q` 全部通过；

5. **观察一次真实抓取**：GUI 里对一个小站点（如 `https://example.com`）发起深度 1 的爬取，看日志输出与 `resources/crawler_cache.db` 里多出来的行。
