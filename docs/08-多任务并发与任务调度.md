# 阶段 08：多任务并发与任务调度

## 阶段目标

- 建立 Python 并发编程的正确心智模型（GIL、线程 vs 进程、队列、线程池）；
- 掌握 Qt 的 `QThread` + 信号槽跨线程协作模式；
- 读懂 `TaskScheduler` 的并发控制、排队补位、持久化与重试设计；
- 能实现一个带优先级的迷你任务调度器。

## 8.1 Python 并发地图

| 概念 | 一句话 | 爬虫中的应用 |
|---|---|---|
| GIL | 同一进程同一时刻只有一个线程跑 Python 字节码 | CPU 密集型（解析、哈希）别指望多线程加速；**IO 密集型（网络等待）多线程有效** |
| 多线程 | 共享内存、切换成本低 | 爬虫主力：请求等待时让出 GIL |
| 多进程 | 绕开 GIL、隔离崩溃 | 本项目未采用（任务级 DB/目录隔离已够） |
| `queue.Queue` / `PriorityQueue` | 线程安全的产销队列 | 下载任务队列 |
| `QThreadPool` | Qt 的线程池 | `manager/thread_manager.py` |
| 信号槽跨线程 | Qt 的线程安全通信机制 | 工作线程 → UI 的进度/日志 |

爬虫是典型 IO 密集型：瓶颈在"等网络响应"，多线程让等待重叠起来。这是"为什么爬虫普遍多线程"的根本原因。

## 8.2 `TaskScheduler`：`manager/task_manager.py`

多任务调度的核心设计：

```
任务队列（按 优先级, 任务ID 排序）
   │
   ▼
┌─────────────────┐     存活任务数 < max_concurrent？
│  排队补位逻辑    │──────────────┬─ 是 ─▶ 启动队首任务（新 QThread）
└─────────────────┘              └─ 否 ─▶ 等待；有任务结束再补位
```

要点拆解：

1. **一任务一线程**：每个爬取任务是独立 `QThread`（内部再用线程池做下载并发）；
2. **并发上限 + 排队补位**：只保留 `max_concurrent` 个存活任务；按 `(优先级, ID)` 排序，空出位就从队首补；
3. **类型分流**：`TaskConfig.media['enabled']` 决定走媒体抓取还是文本递归；
4. **robots 前置检查**：启动前先起线程校验 robots.txt，不阻塞界面；
5. **进度节流 + 队列防抖落盘**：进度信号高频刷新会拖垮 UI，节流后发送；`task_queue.json` 防抖持久化（`save_queue` / `load_queue`），重启恢复队列；
6. **失败重试**：定时器驱动自动重试；
7. **信号跨线程回 UI**：所有工作线程通过 Qt 信号把状态送回界面，**绝不直接碰 UI 控件**（Qt 的线程亲和性规则）。

## 8.3 `ThreadPoolManager`：`manager/thread_manager.py`

- `ThreadPoolManager`：封装 `QThreadPool`，提供异步落盘等杂务执行能力；
- `spawn_workers(N)`：起 N 个守护工作线程，配合 `PriorityQueue` 供下载器消费。

## 8.4 下载器侧的并发（回顾）

`core/downloader.py`：`PriorityQueue` 排序 + 线程池并发 + Range 分块续传。与调度层的关系：**调度层管"任务间并发"（几个站点同时爬），下载层管"任务内并发"（一个站点的多个文件同时下）**。两层并发都要限流，否则会把本机（fd/内存）或对端（频率）拖垮。

## 8.6 动手练习

1. **并发观察**：GUI 多任务队列一次添加 5 个站点任务，把 `max_concurrent` 设为 2，观察同时运行的只有 2 个、其余排队，结束一个补位一个；
2. **队列持久化**：添加任务后找到 `task_queue.json`，删掉一个再重启程序，验证队列恢复；
3. **迷你调度器**：写一个 60 行内的调度器：`PriorityQueue` + `threading.Thread`（daemon），实现"最多 N 个并发、按优先级补位、任务结束发事件"，用 `time.sleep` 模拟任务时长，打印调度顺序；
4. **节流实验**：在练习 3 里模拟"每 10ms 发一次进度"，先直发（界面/控制台卡顿）再加 200ms 节流，对比效果；
5. **线程安全找茬**：故意在迷你调度器里去掉锁共享一个计数器，跑 100 个任务观察结果是否丢失更新（`+=` 非原子），再加上锁修复。
